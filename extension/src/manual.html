Visão geral

O token GD Burti permanece fisicamente conectado ao servidor do escritório. O Cloudflare One Client cria a rota privada e o VirtualHere o apresenta ao computador como USB local. SafeSign e PJeOffice continuam trabalhando normalmente.

Segurança: a chave privada nunca é extraída do token e o Jurius não solicita nem armazena o PIN. Digite o PIN somente na janela do SafeSign ou PJeOffice.

Uso exclusivo: um token físico atende um computador por vez. Ao terminar, clique em Liberar token para a próxima pessoa usar.

1. Ligar a rede privada Cloudflare

Windows e macOS

  1. Baixe a versão estável do Cloudflare One Client correspondente ao seu sistema.
  2. Instale e abra o aplicativo. Selecione Zero Trust security.
  3. Quando pedir o nome da equipe, informe somente equipe-jurius.
  4. O navegador abrirá equipe-jurius.cloudflareaccess.com. Autentique-se com pedro@advcuiaba.com ou outro e-mail previamente autorizado pelo administrador.
  5. Volte ao aplicativo e deixe o botão em Connected/Conectado.

O WARP está configurado com Split Tunnel para levar somente 10.254.75.75/32 ao escritório. Sua navegação normal não deve passar pelo servidor Linux.

Testar no macOS

route -n get 10.254.75.75
nc -vz 10.254.75.75 7575

A rota deve usar uma interface utun e o teste da porta deve informar sucesso.

Testar no Windows (PowerShell)

Test-NetConnection -ComputerName 10.254.75.75 -Port 7575

O resultado esperado é TcpTestSucceeded : True. Com o WARP desligado, deve ser False.

2. Instalar e configurar o VirtualHere Client

  1. Baixe o cliente oficial para Windows ou macOS.
  2. Abra o VirtualHere Client. No macOS, aprove as permissões de sistema solicitadas. No Windows, aceite a instalação do driver quando solicitado.
  3. Clique com o botão direito em USB Servers e escolha Specify Hubs.
  4. Adicione 10.254.75.75:7575. Não use o domínio público do portal.
  5. Expanda Jurius Token Office. O item esperado é StarSign CUT S.
  6. Para um teste manual, clique com o botão direito no token e escolha Use this device. No uso normal, a extensão fará essa solicitação.

Se aparecer This server trial has expired, o servidor ainda está usando configuração avançada incompatível com a edição gratuita. O administrador deve recriar a stack com a versão atual deste projeto.

3. Instalar e validar o SafeSign

  1. Baixe o middleware compatível com o token GD Burti/StarSign e com a versão do seu sistema. Consulte primeiro o fornecedor do certificado; como referência, a Certisign mantém downloads por modelo e sistema.
  2. Instale e reinicie o computador se o instalador solicitar.
  3. Conecte o token no VirtualHere e abra o SafeSign TokenAdmin.
  4. Confirme que o token e o certificado aparecem. Não altere, inicialize nem formate o token.

Não teste PIN repetidamente. Tokens A3 bloqueiam após um número limitado de tentativas incorretas.

4. Instalar e validar o PJeOffice Pro

  1. Baixe o instalador correto na página oficial do PJeOffice Pro: Windows 64 bits, Mac Intel ou Mac Apple Silicon.
  2. Instale e abra o PJeOffice Pro antes de entrar no PJe.
  3. Nas configurações de certificado, confirme que o SafeSign/PKCS#11 e o certificado aparecem.
  4. Abra o PJe no Chrome, escolha Certificado Digital, autorize a comunicação com o PJeOffice e faça uma assinatura de homologação.

5. Instalar a ponte local e a extensão

  1. Instale o companion Jurius no computador seguindo o instalador de Windows ou macOS fornecido pela equipe.
  2. No Chrome, abra chrome://extensions, habilite o modo do desenvolvedor e carregue a pasta extension sem compactação durante o MVP.
  3. Fixe a extensão na barra do Chrome. Abra-a e use o botão de atualizar.

Uso diário

  1. Ligue o Cloudflare One Client/WARP.
  2. Abra VirtualHere Client, SafeSign e PJeOffice Pro.
  3. Abra a extensão e clique em Conectar token.
  4. Acesse o PJe e assine normalmente. Informe o PIN apenas quando o SafeSign/PJeOffice solicitar.
  5. Ao concluir, clique em Liberar token. A reserva também expira automaticamente após cinco minutos.

Solução de problemas

“Enrollment request is invalid”

A política de Device Enrollment não está associada ou o e-mail não corresponde. O administrador deve associar uma política Allow contendo o e-mail exato; depois remova o registro antigo no WARP e matricule novamente.

Rede privada offline

Confirme WARP conectado e equipe equipe-jurius. Execute o teste da porta acima. Se falhar, verifique rota CIDR 10.254.75.75/32, Split Tunnel e saúde do túnel.

Servidor aparece, mas o token não

O administrador deve confirmar no Linux que lsusb mostra 1059:0019 e que o log do VirtualHere mostra Found ... StarSign CUT S.

Token “Em uso”

Outro computador detém o USB. Espere a pessoa liberar ou a reserva expirar. Um token físico não pode ser conectado simultaneamente a dois computadores.

SafeSign não mostra o certificado

Primeiro confirme que o VirtualHere mostra o dispositivo em uso neste computador. Depois reinicie TokenAdmin. Se persistir, reinstale a versão correta do middleware para o sistema e arquitetura.

PJeOffice não encontra o certificado

Confirme o certificado no TokenAdmin, encerre e reabra o PJeOffice depois de conectar o USB, confira a biblioteca PKCS#11 configurada e só então reabra o PJe.
